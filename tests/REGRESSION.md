# 重构回归测试清单

本文档定义了 `txtToWorldbook` 模块重构后的回归测试场景。每次涉及核心逻辑变更的发布前，必须完成以下手动测试。

> **前置条件**：SillyTavern 1.10+ 已正常运行，插件已加载，至少有一个可用的 AI 连接。

---

## 一、基础功能验证

### 1. 打开插件弹窗

**操作步骤**：

1. 点击插件面板中的「TXT 转世界书」按钮

**预期结果**：

- [ ] 模态框正常弹出
- [ ] 显示 API 配置面板
- [ ] 显示「上传 TXT」区域
- [ ] 各面板折叠/展开正常
- [ ] 无控制台错误

**常见问题排查**：

- 弹窗无响应：检查 `window.TxtToWorldbook.open()` 是否可达
- 样式错乱：检查 `style.css` 和 `modalStyles.js` 是否正确加载

---

### 2. 加载 TXT 并完成一次完整转换

**操作步骤**：

1. 上传一个包含至少 3 章内容的 TXT 文件（UTF-8 编码）
2. 确认章节自动分块成功
3. 选择酒馆 API（或其他可用 API）
4. 点击「开始转换」
5. 等待处理完成

**预期结果**：

- [ ] 文件上传成功，文件名正确显示
- [ ] 章节队列自动识别（至少 3 个章节块）
- [ ] AI 正常返回数据
- [ ] 世界书结构正确生成
- [ ] 处理进度条正常更新
- [ ] 最终结果显示「处理完成」

**常见问题排查**：

- 上传失败：检查 `fileUtils.js` 编码检测
- AI 返回空/报错：检查 `apiService.js` 的调用逻辑
- 世界书为 null：检查 `parserService.js` 解析

---

### 3. 串行模式处理

**操作步骤**：

1. 关闭「并行处理」开关
2. 上传一个 TXT 文件
3. 开始处理

**预期结果**：

- [ ] 章节按顺序逐个处理
- [ ] 每个章节完成后才处理下一个
- [ ] 后续章节的 prompt 包含前序积累的世界书摘要
- [ ] 结果连贯，无明显重复

---

### 4. 并行独立模式处理

**操作步骤**：

1. 开启「并行处理」
2. 模式选择「独立模式」
3. 并发数设为 3
4. 开始处理

**预期结果**：

- [ ] 多个章节同时处理
- [ ] 并发数未超过设置值
- [ ] 所有处理完成后世界书生成
- [ ] 无竞态条件错误

---

### 5. 并行分批模式处理

**操作步骤**：

1. 开启「并行处理」
2. 模式选择「分批模式」
3. 并发数设为 3
4. 开始处理

**预期结果**：

- [ ] 每批并行处理，批次间串行
- [ ] 批次间摘要同步正常（后批次感知前批次条目）
- [ ] 总时间明显优于串行模式但仍保持连贯
- [ ] 世界书中条目无明显重复

---

### 6. 暂停与继续恢复

**操作步骤**：

1. 开始处理
2. 在处理到第 2 章时点击暂停
3. 等待当前章节完成
4. 点击继续

**预期结果**：

- [ ] 暂停后当前章节仍完成处理
- [ ] 状态显示「已暂停」
- [ ] 继续后从暂停位置恢复
- [ ] 进度条正确反映实际进度
- [ ] 不重复处理已完成的章节

---

### 7. 修复失败章节

**操作步骤**：

1. 通过特殊设置（如极小的每块字数 + 严格 prompt）强制触发 Token 超限错误
2. 等待失败
3. 点击「修复失败」

**预期结果**：

- [ ] 失败章节被自动从中间分裂为两块
- [ ] 修复流程重新处理分裂后的子块
- [ ] 修复后世界书包含预期的条目
- [ ] 无死循环

---

### 8. 单章重 Roll

**操作步骤**：

1. 完成一次处理
2. 在章节队列中找到一个已完成章节
3. 点击「重 Roll」按钮
4. 确认重 Roll

**预期结果**：

- [ ] 该章节被重新处理
- [ ] AI 重新生成数据
- [ ] 世界书相应更新
- [ ] 修改历史中记录本次变更

---

### 9. 单条目重 Roll

**操作步骤**：

1. 打开世界书预览
2. 找到一个已有条目
3. 点击条目旁的「重 Roll」按钮
4. 可选：附加额外提示词

**预期结果**：

- [ ] 只有该条目被重新生成
- [ ] 其他条目保持不变
- [ ] 条目的 Roll 历史可在详情查看

---

### 10. 批量重 Roll

**操作步骤**：

1. 使用搜索功能找到一批条目（如搜索关键词「角色」）
2. 点击「全部重 Roll」

**预期结果**：

- [ ] 所有匹配的条目被重新生成
- [ ] 不匹配的条目不受影响
- [ ] 处理进度正确显示

---

## 二、世界书操作

### 11. 世界书预览与详细视图

**操作步骤**：

1. 处理完成后查看结果面板
2. 点击「查看世界书」

**预期结果**：

- [ ] 世界书按分类组织显示
- [ ] 每个条目显示名称、关键词、内容
- [ ] Token 计数正确
- [ ] 展开条目可查看详情
- [ ] 编辑按钮可编辑条目

---

### 12. 搜索与替换

**操作步骤**：

1. 点击「查找」按钮
2. 输入关键字
3. 点击「查找全部」
4. 在结果中点击「替换」

**预期结果**：

- [ ] 匹配条目高亮显示
- [ ] 搜索支持全文/关键词
- [ ] 替换前可预览匹配
- [ ] 替换后所有条目的关键词/内容同步更新
- [ ] 替换前自动保存世界书快照

---

### 13. 历史查看与回滚

**操作步骤**：

1. 点击「查看历史」
2. 浏览历史列表
3. 选择一个历史版本
4. 点击「回滚」

**预期结果**：

- [ ] 历史按时间倒序排列
- [ ] 每条历史显示变更摘要
- [ ] 回滚后世界书恢复到指定版本
- [ ] 回滚点及之后的历史记录被移除
- [ ] 回滚操作本身被正确记录

---

### 14. 手动合并 / 别名合并 / 整理条目

**操作步骤**：

**手动合并**：

1. 点击「手动合并」按钮
2. 跨分类勾选 2-3 个条目
3. 指定主名称和目标分类
4. 确认合并

**别名合并**：

1. 点击「自动别名合并」
2. 系统自动检测疑似同名条目
3. 审核合并计划
4. 确认执行

**整理条目**：

1. 点击「整理条目」
2. 选择要整理的分类
3. 确认执行

**预期结果**：

- 手动合并：
  - [ ] 选中的条目合并为一个
  - [ ] 指定分类下出现合并后条目
  - [ ] 原分类下原条目被移除
  - [ ] 关键词和内容为合并结果

- 别名合并：
  - [ ] AI 正确识别疑似同名词组
  - [ ] 两两判断结果合理
  - [ ] 合并后关键词集合完整
  - [ ] 合并前自动保存快照

- 整理条目：
  - [ ] AI 优化去除重复信息
  - [ ] 格式标准化
  - [ ] 不丢失关键信息
  - [ ] 整理前自动保存快照

---

### 15. 设置/任务/世界书导入导出

**操作步骤**：

1. **导出配置**：点击「导出配置」→ 下载配置文件
2. **导出任务**：处理过程中点击「导出任务」→ 下载任务文件
3. **导出世界书**：处理完成后点击「导出世界书」→ 下载 JSON
4. **导入配置**：点击「导入配置」→ 上传配置文件 → 确认覆盖
5. **导入任务**：点击「导入任务」→ 上传任务文件 → 确认恢复
6. **导出变更**：点击「导出变更」→ 对比上次导出的时间戳

**预期结果**：

- [ ] 所有导出功能生成正确文件
- [ ] 世界书 JSON 格式符合 SillyTavern 规范
- [ ] 导入配置后插件行为与新配置一致
- [ ] 导入任务后进度、世界书、队列完全恢复
- [ ] 导出变更仅包含新增/修改条目

---

### 16. 角色卡导出

**操作步骤**：

1. 处理完成后点击「导出角色卡」
2. 在 SillyTavern 中导入生成的角色卡

**预期结果**：

- [ ] 角色卡文件成功生成
- [ ] 包含完整世界书
- [ ] 在酒馆中可正常绑定使用

---

### 17. 断点续传自动恢复

**操作步骤**：

1. 开始处理
2. 处理到第 5 章时，强制刷新浏览器 (Ctrl+F5)
3. 重新打开插件弹窗

**预期结果**：

- [ ] 弹出恢复提示
- [ ] 确认后恢复到中断位置
- [ ] 前 5 章的世界书数据已恢复
- [ ] 章节队列显示已处理状态
- [ ] 从第 6 章继续处理

**补充测试**：

- 关闭恢复提示 → 开始新任务（不恢复）
- 多次刷新 → 仍能正确恢复

---

### 18. API 重试与预算

使用本地故障响应或模拟服务，验证连续 429/503 最多请求 4 次、401 不重试、无效内容最多重试一次；取消退避后不再发请求。酒馆超时后确认不会自动重复生成。请求层与章节集成的自动化用例见 `tests/infra/apiCaller.retry.test.js` 和 `tests/services/apiService.retry.test.js`。真实酒馆超时行为仍需宿主回归。

## 四、回归流程

### 发布前完整回归步骤

1. **运行自动化测试**：

   ```bash
   npm test
   ```

   确保全部自动化用例通过。

2. **手动验证清单**：按顺序完成 1～18 项测试，每项勾选对应复选框。

3. **高风险场景重点复核**：
   - 并行分批模式 + 摘要同步（场景 5）
   - 别名合并（场景 14）
   - 断点续传恢复（场景 17）
   - Token 超限分裂（场景 7）

4. **跨浏览器验证**：至少在 Chrome 和 Firefox 各跑一遍关键流程。

### 回归判定标准

- **所有自动化测试通过**（必需）
- **所有手动清单勾齐**（必需）
- **无新增控制台错误**
- **无功能退化**
