# 重构回归测试清单

本文档定义了 `txtToWorldbook` 模块重构后的回归测试场景。每次涉及核心逻辑变更的发布前，按以下场景验证；可用相同业务断言的自动化测试替代重复手动步骤。1.9.0 的真实宿主操作、Vitest 场景和未覆盖范围见 [验收记录](../docs/host-smoke.md)；此处复选框是可复用模板，不代表本次每个按钮均做过人工点击。

> **前置条件**：SillyTavern 1.10+ 已正常运行，插件已加载，至少有一个可用的 AI 连接。

---

## 一、基础功能验证

### 1. 打开插件弹窗

**操作步骤**：

1. 点击插件面板中的「TXT 转世界书」按钮

**预期结果**：

- [ ] 模态框正常弹出
- [ ] 显示 API 配置面板
- [ ] 显示「上传 TXT」区域
- [ ] 各面板折叠/展开正常
- [ ] 无控制台错误

**常见问题排查**：

- 弹窗无响应：检查 `window.TxtToWorldbook.open()` 是否可达
- 样式错乱：检查 `style.css` 和 `modalStyles.js` 是否正确加载

---

### 2. 加载 TXT 并完成一次完整转换

**操作步骤**：

1. 上传一个包含至少 3 章内容的 TXT 文件（UTF-8 编码）
2. 确认章节自动分块成功
3. 选择酒馆 API（或其他可用 API）
4. 点击「开始转换」
5. 等待处理完成

**预期结果**：

- [ ] 文件上传成功，文件名正确显示
- [ ] 章节队列自动识别（至少 3 个章节块）
- [ ] AI 正常返回数据
- [ ] 世界书结构正确生成
- [ ] 处理进度条正常更新
- [ ] 最终结果显示「处理完成」

**常见问题排查**：

- 上传失败：检查 `fileUtils.js` 编码检测
- AI 返回空/报错：检查 `apiService.js` 的调用逻辑
- 世界书为 null：检查 `parserService.js` 解析

---

### 3. 串行模式处理

**操作步骤**：

1. 关闭「并行处理」开关
2. 上传一个 TXT 文件
3. 开始处理

**预期结果**：

- [ ] 章节按顺序逐个处理
- [ ] 每个章节完成后才处理下一个
- [ ] 后续章节的 prompt 包含前序积累的世界书摘要
- [ ] 结果连贯，无明显重复

---

### 4. 并行独立模式处理

**操作步骤**：

1. 开启「并行处理」
2. 模式选择「独立模式」
3. 并发数设为 3
4. 开始处理

**预期结果**：

- [ ] 多个章节同时处理
- [ ] 并发数未超过设置值
- [ ] 所有处理完成后世界书生成
- [ ] 无竞态条件错误

---

### 5. 并行分批模式处理

**操作步骤**：

1. 开启「并行处理」
2. 模式选择「分批模式」
3. 并发数设为 3
4. 开始处理

**预期结果**：

- [ ] 每批并行处理，批次间串行
- [ ] 批次间摘要同步正常（后批次感知前批次条目）
- [ ] 总时间明显优于串行模式但仍保持连贯
- [ ] 世界书中条目无明显重复

---

### 6. 暂停与继续恢复

**操作步骤**：

1. 开始处理
2. 在处理到第 2 章时点击暂停
3. 等待当前章节完成
4. 点击继续

**预期结果**：

- [ ] 暂停后当前章节仍完成处理
- [ ] 状态显示「已暂停」
- [ ] 继续后从暂停位置恢复
- [ ] 进度条正确反映实际进度
- [ ] 不重复处理已完成的章节

---

### 7. 修复失败章节

**操作步骤**：

1. 通过特殊设置（如极小的每块字数 + 严格 prompt）强制触发 Token 超限错误
2. 等待失败
3. 点击「修复失败」

**预期结果**：

- [ ] 失败章节被自动从中间分裂为两块
- [ ] 修复流程重新处理分裂后的子块
- [ ] 修复后世界书包含预期的条目
- [ ] 无死循环

---

### 8. 单章重 Roll

**操作步骤**：

1. 完成一次处理
2. 在章节队列中找到一个已完成章节
3. 点击「重 Roll」按钮
4. 确认重 Roll

**预期结果**：

- [ ] 该章节被重新处理
- [ ] AI 重新生成数据
- [ ] 世界书相应更新
- [ ] 修改历史中记录本次变更

---

### 9. 单条目重 Roll

**操作步骤**：

1. 打开世界书预览
2. 找到一个已有条目
3. 点击条目旁的「重 Roll」按钮
4. 可选：附加额外提示词

**预期结果**：

- [ ] 只有该条目被重新生成
- [ ] 其他条目保持不变
- [ ] 条目的 Roll 历史可在详情查看

---

### 10. 批量重 Roll

**操作步骤**：

1. 使用搜索功能找到一批条目（如搜索关键词「角色」）
2. 点击「全部重 Roll」

**预期结果**：

- [ ] 所有匹配的条目被重新生成
- [ ] 不匹配的条目不受影响
- [ ] 处理进度正确显示

### 18. API 重试与预算

使用本地故障响应或模拟服务，验证连续 429/503 最多请求 4 次、401 不重试、无效内容最多重试一次；取消退避后不再发请求。酒馆超时后确认不会自动重复生成。请求层与章节集成的自动化用例见 `tests/infra/apiCaller.retry.test.js` 和 `tests/services/apiService.retry.test.js`。真实酒馆超时行为仍需宿主回归。

### 19. 响应完整性与取消

通过本地可控流模拟部分正文后停滞、异常 EOF、长度截断、错误事件、UTF-8 拆包和 CRLF；验证失败时不提交残片，取消/完成后无残留 reader 与计时器。JSON 正文读取也必须受总超时约束。自动化用例见 `tests/infra/apiCaller.stream.test.js`。兼容服务若省略结束标记，必须经验证后显式启用 EOF 兼容，不默认放行。

## 四、回归流程

### 发布前完整回归步骤

1. **运行自动化测试**：

   ```bash
   npm test
   ```

   确保全部自动化用例通过。

2. **手动验证清单**：按顺序完成 1～19 项测试，每项勾选对应复选框。

3. **高风险场景重点复核**：
   - 并行分批模式 + 摘要同步（场景 5）
   - 别名合并（场景 14）
   - 断点续传恢复（场景 17）
   - Token 超限分裂（场景 7）

4. **跨浏览器验证**：至少在 Chrome 和 Firefox 各跑一遍关键流程。

### 回归判定标准

- **所有自动化测试通过**（必需）
- **所有手动清单勾齐**（必需）
- **无新增控制台错误**
- **无功能退化**

## B03 续写与运行隔离

- 续写发送后无回复、持续生成或 toast 持续存在时等待有上限；未确认回复不推进章节、不重复发送。
- 等待期间停止再开、切换聊天或手动追加消息，旧回调不推进新任务。短回复不累计成功章节、不触发完成导出。
- 世界书主转换停止时阻止立即重开，旧请求收尾后恢复按钮；旧响应不合并、不保存为成功。
- 并发许可已获取但尚未执行时停止，许可正确释放；致命错误停止队列且保留原错误。
- 宿主生成无法取消时本地退出等待，后续请求等上游结束；排队期间超时的请求不补发。

对应自动化：tests/novel/generation.test.js、tests/services/processingService.test.js、tests/services/apiService.retry.test.js。宿主界面操作需在真实酒馆补验。

## B04 任务控制与恢复预算

- 转换暂停后只保存已发任务，乱序响应按章节顺序提交；恢复跳过成功块。关闭主面板触发保存后暂停。
- 修复、章节重 Roll、条目重 Roll 期间启动其他任务应被拒绝；取消后的结果不保存，按钮与运行锁在收尾后释放。
- 自动分卷连续超限、拆分子块再次超限时，恢复预算耗尽后明确失败，不无限递归。
- 批量重 Roll 致命错误不继续发送排队任务；旧运行不隐藏新运行的操作按钮。

对应自动化：runContext、processingService、repairService、rerollService、modalController 测试。真实宿主 UI 仍需补验。

## B05 供应商适配

- Gemini、Anthropic、OpenAI 兼容模式分别执行模型测试与实际转换；核对消息链、认证、端点与流模式一致。
- Anthropic 系统消息使用顶层 system；Gemini 带查询参数的代理地址路径正确、密钥不出现在请求 URL 日志中。
- 模型列表使用原生接口和分页；认证错误、分页循环、截断/阻断响应应明确失败。
- 酒馆普通内部异常不触发格式回退；仅明确参数签名不兼容可回退。

自动化对应 providers.test.js 与 apiService.retry.test.js；实际 CORS/供应商能力尚未验证。
