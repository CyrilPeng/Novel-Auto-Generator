# 发布与回退

## 1.9.0 更新前

1. 停止任务，等待已发请求收尾。自动续写若有待确认发送，应先回原聊天核对回复。
2. 使用“导出任务”保存当前章节和完整成果，再单独导出世界书。任务包含小说文本，请妥善保存。
3. 备份浏览器站点数据。API 凭据不在普通导出文件中，需自行保存其来源或重新配置。
4. 通过酒馆扩展管理器更新本插件，刷新页面。仓库安装入口仍为根目录 `index.js` 和 `style.css`，更新时需要完整仓库，不能只覆盖单个 JS。

新版本仍读取旧检查点，数据库版本保持 7。首次保存新检查点前会保留旧状态；“迁移前备份”导出它，没有旧状态时明确提示。备份仅代表升级前状态，不包含升级后生成的新内容。

## 回退且保留新成果

1. 停止任务并导出最新任务和世界书；如需升级前状态，另外导出“迁移前备份”。
2. 保留当前浏览器站点备份。在独立浏览器资料或测试酒馆中安装重构前代码 `c333ca2`（或所需旧 tag）。
3. 打开旧版插件，导入最新任务文件，核对章节数、完成状态及世界书内容，再重新导出一份成果。
4. 核对成功后再决定是否将日常环境切换到旧版。不要为了降级清空唯一一份站点数据。

旧代码导入新版本三块已完成任务的演练已通过，见 [验收记录](host-smoke.md)。新版本专有的运行保护与编辑覆盖层不能由旧代码继续维护；需要长期保留的最终内容应额外保存为世界书文件。

## 维护者发布步骤

1. 更新 CHANGELOG、`manifest.json`、`package.json` 和锁文件中的版本。
2. `npm ci`、`npm run verify`，执行两版真实宿主脚本、回退脚本及大文本压力检查。
3. 提交已验证修改，确保 main 包含该提交，推送后等待 CI 的 Node 20/22 检查通过。
4. 在已验证提交创建 `v1.9.0` tag，推送 tag，创建 GitHub Release。发布说明列明模型 fixture 和移动视口验收范围。
5. 检查 Release URL、tag 对应提交与远端 main。不要把单元测试通过描述为真实模型服务已通过验证。

阶段提交均采用 `<type>(<scope>): 中文描述`，提交前同步 CHANGELOG。依赖与测试工具属于开发环境，不是酒馆安装所需的构建步骤。
